## 配置

| 操作 | 挙動 |
| --- | --- |
| 中央 | サイズを保って作業領域の中央へ。Ubuntu版では大きすぎる場合は領域内に収める |
| 最大化 | GNOMEの最大化。アプリの全画面モードにはしない |
| 左右半分 | 幅を 1/2 → 2/3 → 1/3 → 1/2、配置する側の辺は画面端に固定 |
| 上下半分 | 高さを 1/2 → 2/3 → 1/3 → 1/2、配置する側の辺は画面端に固定 |
| 四隅 | **高さは1/2を維持**し、幅を 1/2 → 2/3 → 1/3 → 1/2 |
| 次の1/3 | 左 → 中央（横）→ 右 → 上 → 中央（縦）→ 下 → 左 |
| 前の1/3 | 上記の逆順。左から前へ進むと下 |

半分・四隅の切り替えは「同じキーを押した履歴」ではなく、**現在のウィンドウがどの領域に一致するか**で判断します。アプリの制約で少し小さくても、対象領域の中央に収まっていれば一致とみなします。

次／前の1/3も現在の位置・サイズから判断し、どの領域にも一致しない場合は、**どちらの方向でも最初は左1/3**になります。「半分・四隅のサイズ切り替え」を無効にしても、次／前の1/3巡回は使えます。

本家ソースの切り替え順は **1/2 → 2/3 → 1/3** です。Window Atlasでもこの順序を使用します。

## 拡大・縮小

本家は割合指定ではなく、幅・高さをそれぞれ **±30px** 変えます。Ubuntu版も初期値を±30論理pxとし、設定で5～200に変更できます。

- 端に接していない場合は中心を維持する。
- 左・右・上・下のいずれかに接していれば、その端との接触を維持する。
- 左右の両端に接している場合は幅を維持し、高さだけ変更する。
- 上下の両端に接している場合は高さを維持し、幅だけ変更する。
- **全4辺に接した状態から縮小する場合だけ**、両寸法を減らして中央を維持する。
- 本家同様、端から5論理px以内は接触とみなす。
- 変更後の幅または高さが作業領域の1/4以下になる場合、変更全体を実行しない。

画面外へはみ出す場合、Ubuntu版は作業領域内に収めます。すき間設定で画面端から5pxより大きく離れている辺は、接触とはみなしません。

## ディスプレイ間移動

本家の `SpectacleNextOrPreviousDisplay.js` に合わせ、移動先に現在の幅・高さが収まる場合は、**サイズを変えずに中央へ配置**します。どちらか一方でも収まらない場合は、移動先の作業領域いっぱいに配置します。以前の試作にあった、相対位置・相対サイズを比例変換する処理は廃止しました。

移動先いっぱいになった場合はGNOMEの最大化状態とし、それより大きい画面へ移すと、サイズを保った通常ウィンドウになります。Undoでは移動前のモニター・位置・サイズ・最大化状態を復元します。

モニターの巡回順はUbuntu版ではMutterのモニター番号順です。macOSのディスプレイ列挙順と同じとは限りません。

## キー配列

初期値はGNOME標準キーの変更を避けるUbuntu向け配列です。**既存ユーザーの割り当てを無断でSpectacle配列へ切り替えません。** 設定画面から確認付きで選択できます。

Spectacle配列は、CommandをSuper、OptionをAltに対応させた本家18操作です。

| 操作 | Spectacle配列 |
| --- | --- |
| 中央／最大化 | Alt + Super + C / F |
| 上下左右半分 | Alt + Super + 矢印 |
| 左上／右上 | Ctrl + Super + ← / → |
| 左下／右下 | Ctrl + Shift + Super + ← / → |
| 次／前のディスプレイ | Ctrl + Alt + Super + → / ← |
| 次／前の1/3 | Ctrl + Alt + → / ← |
| 拡大／縮小 | Ctrl + Alt + Shift + → / ← |
| Undo／Redo | Alt + Super + Z / Alt + Shift + Super + Z |

**GNOMEのワークスペース操作等と競合するキーがあります。** 適用前に既知の競合を表示しますが、他の拡張や直接キーを取得するアプリをすべて検出できるわけではありません。OS側のキーを自動解除しないため、競合を解消しなければ使えない組み合わせがあります。Ubuntu向け配列・個別編集も選べます。

プリセットは本拡張内の全キーを置き換えます。Spectacle配列では、本家にない位置記憶・直接1/3・2/3配置や「最初の状態に復元」のキーは未設定です。メニュー操作は残ります。

## プラットフォーム差・対象外

これはmacOS版バイナリの移植・完全互換エミュレーターではありません。

- 座標はMutterの論理px。Cocoaの左下原点を左上原点に置き換えています。
- 奇数の解像度では領域の境界を共有するように丸めるため、本家の切り捨て計算と1～2px異なる場合があります。領域一致の許容差も2論理pxです。
- メニューバーはGNOMEのパネルメニュー、アクセシビリティ操作はMutter APIに置き換えています。
- GNOMEの最大化状態・履歴復元を扱います。macOSの全画面モードの制御はしません。
- 操作履歴はウィンドウごとで、ログアウト／拡張の無効化までのメモリ内保存です。これとは別に、[位置の永続記憶・復元](position-memory.md) を提供しています。
- GNOME拡張の有効化状態は次回ログイン時にも適用されるため、別途の自動起動デーモンは不要です。
- 本家にある端末の制約に対する反復縮小・領域内中央寄せを、そのまま再現してはいません。アプリの最小サイズ・文字単位リサイズ等にはMutterとクライアントの制約が適用されます。
- Waylandで移動とリサイズの応答がずれ、隣のモニターに制限される場合は、一度だけ再配置を要求します。800msを上限とし、アプリの制約に対して無限に再試行しません。
- KDE、Xfce、Swayは対象外です。GNOME 45～50を対象にしていますが、実行確認環境はGNOME 50.1です。

## 動作確認

自動テスト:

```bash
npm test
python3 tools/manage.py validate
python3 tools/smoke.py prefs
python3 tools/smoke.py shell
```

Shellテストでは通常のデスクトップと分離したHOME・XDG・D-Bus環境に2つの仮想モニターを用意し、GTK Waylandウィンドウと仮想キーボードを使います。通常のデスクトップへのインストールやOSキーの解除はしません。

手動確認は、インストール・ログインし直し・有効化後に、まずUbuntu向け配列で行います。

1. 通常サイズのウィンドウで、左半分のキーを4回押す。幅が1/2 → 2/3 → 1/3 → 1/2となること。
2. 左上・右上・左下・右下でも各4回押す。高さは半分のまま、幅だけ同じ順に変わること。
3. 次の1/3を繰り返し、横3領域 → 縦3領域 → 左へ戻ること。前の1/3で逆に巡回すること。
4. 左半分から縮小し、左端・上下端が維持されて幅だけ30px減ること。右半分でも右端を維持すること。
5. 最大化から縮小し、各端から15pxずつ離れること。Undoで最大化に戻ること。
6. サイズの異なるディスプレイ間で、収まる場合は同じサイズで中央へ、収まらなければ移動先いっぱいになること。
7. 新しい操作のUndo／Redoと、最初の位置への復元を確認すること。
8. 設定でプリセット適用を一度キャンセルし、変更されないこと。適用時は表示される競合を確認すること。

Firefox、端末、Electronアプリ、異なる物理モニターの拡大率などは、利用環境ごとの追加確認が必要です。

## Window Atlasの追加機能

本家の配置操作に加え、ローカルJSONへの位置記憶・復元を提供します。自動記憶と起動時の自動復元は独立した設定です。固定レイアウトを保存する場合は自動記憶を無効にしてから全ウィンドウを記憶してください。詳細は [位置記憶の仕様](position-memory.md) と [日本語ガイド](guide.ja.md) に記載しています。

開発中の旧 `spectacle-ubuntu@local` 拡張を手動で導入していた場合は、二重にキーを取得しないよう旧拡張を無効にしてからWindow Atlasを有効にしてください。新しいUUID・スキーマを使用するため、旧試作の設定を自動で書き換えることはありません。
